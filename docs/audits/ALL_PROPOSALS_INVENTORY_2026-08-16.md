# H. Продуктовое определение — 7 пунктов

### 90. v1 = подготовленный текст → Short
`GPT OD-A` · `2.1 OD-17` · `2.1 OD-20` — **✅ это признание, а не выбор**
GPT предлагает выбрать вариант A и отложить `тема → исследование → сценарий`.
Репозиторий показывает, что выбирать нечего: исследование — заглушка,
сценарий — извлекающая компоновка. Это не отсрочка, а описание существующего
состояния. Вместе с ним признаётся, что интерфейс обещает больше, чем делает
(п. 81).

### 91. Человеческая проверка обязательна для v1
`GPT §13, OD-D` — **✅ уже current truth**

«человеческая проверка кадров не выявила показано не то».

### 92. Разделить «ручная правка не нужна» и «человек подтверждает»
`GPT §13` — **✅**
Идеальный прогон v1: система сама выбирает хороший материал → владелец смотрит
→ ничего не исправляет → подтверждает. Это существенно отличается от
автопубликации, и приёмку надо формулировать так, чтобы разница была видна.

### 93. Не утверждать `6/24` до первого замера
`GPT §14, OD-F` — **✅**
Сначала стенд печатает базовый уровень на корпусе v2, потом владелец называет
целевое улучшение. Иначе число выбирается без понимания, насколько трудны новые
сцены.

### 94. Beta = ≥2/3, релиз v1 = 3 подряд на ≥3 доменах
`ПМ P6` (≥2/3) · `GPT §20` (строже для релиза) — **⚠️**

на разных темах». Любое число здесь — новое обязательство, а не сверка с
планом. Это надо сказать владельцу прямо, а не подставлять цифру молча.

### 95. Платный смысловой бриф по умолчанию для RU-каналов
`ПМ §5.1 (PD-5)` · `GPT OD-B` — **❓ решение владельца**
Проверено: бриф сегодня **opt-in** (`enabled: false`). Без него русский проект
**не отправляет на сток ни одного запроса** — «бесплатный офлайн-режим» на стоке
не существует, только локальная библиотека. GPT прав, что менять старое решение
молча нельзя. Рабочая форма: канал может выбрать бриф как намеренного
провайдера, платный вызов всё равно требует подтверждения; без подтверждения —
только локальная библиотека или явное «требуется перевод», а не молчаливый
плохой поиск.

`GPT OD-E` — **✅ подтверждено в коде**
`DEFAULT_MIN_VIDEO_DURATION_RATIO = 0.4` существует. Смысл и права остаются
приоритетом: плохое видео не повышается ради показателя.
