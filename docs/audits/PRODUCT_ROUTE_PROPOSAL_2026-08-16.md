# Предложение продуктового маршрута — от черновика к публикуемому Short

Это **предложение**, не план: PLAN-ID не создаёт, статусов не меняет, решений
владельца не выдаёт. Если принято — растворяется в
`docs/current/PROJECT_EXECUTION_PLAN.md`; если нет — остаётся evidence мнения.
Основано на [PRODUCT_AUDIT_2026-08-16.md](PRODUCT_AUDIT_2026-08-16.md) и
согласовано с маршрутом аудита 08-15 (пакет SEL-1 = В1, стенд = В2, субтитры =
В10, пороги LIVE = В11): я не предлагаю параллельного пакета, я предлагаю
**состав и порядок внутри той же линии**, плюс то, чего в ней нет.

Только продукт. Governance-диета (ревизия 2.2) идёт своей дорогой; единственная
точка контакта — этот документ живёт в `docs/audits`, а не в плане.

## 1. Один принцип

**Публикуемый Short = правильный кадр × читаемый × движущийся × честный ×
дешёвый.** Каждое слово — число, и пакет закрывается числом, а не записью:
«по смыслу N/5», «видео-слотов ≥ 1 и ≥ 40 % длительности», «MP4 ≠
no_subtitles», «publish_ready в strict без ручной замены», «$ на принятый ролик».

Второй принцип — порядок: **сначала прибор, потом рычаги, потом платный прогон**.
Три прогона подряд стоят на 2/5 по смыслу не потому, что нечего чинить, а потому,
что чинили не то, что мерили, и мерили не то, что чинили (пин 4/14 на английском
корпусе не видит двуязычную библиотеку и русские окончания по построению).

## 2. Что я предлагаю считать v1 (числа — на утверждение владельцу)

| Свойство | Порог v1 |
|---|---|
| Вход | 250–400 символов RU-текста + канал; **одна** команда + одно платное подтверждение; без правки конфигов между прогонами |
| Смысл | ≥ 4/5 сцен «верно по смыслу» при слепой проверке владельца; 0 `must_avoid`, 0 вводящих в заблуждение кадров |
| Движение | ≥ 1 видео-слот и ≥ 40 % длительности видео (действующая `video_first_policy`) — либо явный opt-in «стиллы с движением» на уровне канала |
| Читаемость | субтитры вшиты; хук-заголовок в первые 1,5 с (если владелец включит) |
| Честность | `publish_ready=true` в `strict` без ручной замены слота; права verified; каталог не обещает несуществующего; CLI печатает все пути результата |
| Повторяемость | **3 из 4** последовательных прогонов на **трёх разных темах** (животные · энергетика · география — три reference-домена PLAN-11) |
| Цена и время | ≤ $0,50 платных вызовов + 1 TTS на ролик; ≤ 10 мин wall-clock, поиск ≤ 5 мин |

Это совпадает с beta-критериями `PRODUCT_PLAN.md §10` и добавляет к ним только
числа. То, что v1 **не** включает: Vision по умолчанию, музыка с поиском,
метаданные площадок, UI, longform, user assets через CLI (PD-4 — отдельный
слайс, если владелец поднимет приоритет).

### P1 · Смысл (3–4 сессии, $0 офлайн) — ядро SEL-1, в этом порядке

1. **Доказуемость по полю, не по склеенному тексту** — `evidence.py:413-417`
   (`is_undecidable` спрашивает поле, из которого берётся балл) + характеризация:
   тот же курированный клип 7,5 → ≥ 78. Первым, потому что без него п. 2 отклоняет
   правильный материал как `semantic_unverified`. Замер на корпусе v1: ожидание
   «ноль изменившихся победителей» — измерить, не выводить.
2. **Предметное существительное — жёстко.** Бриф отдаёт ещё два поля в том же
   вызове (цена не меняется): `must_include` (1–2 английских существительных) и
   английские `must_avoid`; детерминированный путь заполняет `must_include` из
   `subject`, если бриф выключен. Порог `exact_subject` перестаёт быть advisory
   при `partial_support`, когда `must_include` задан. Проверено офлайн: обе
   картинки Opel → `must_include_missing`.
3. **Обратная сверка брифа с нарративом**: если ни одно из `must_include` не
   встречается в исходном тексте сцены (в любой форме) — бриф помечается
   `needs_review`, а не идёт в поиск молча (класс «factory production line без
   solar»).
4. Локальная библиотека: читать `use_local_library` там, где формируется пул,
   либо удалить ключ (`C83`); `media_library._score_asset` учитывает
   `title`/`description`, `min_score` > 1; `C47` — по решению владельца.
5. Дедупликация шортлиста по identity до промоушена и до доски ревью.
6. `query_not_allowed_for_scene`: либо не отбрасывать явные запросы брифа, либо
   писать причину в `query_plan`.
7. `C77` (форма запроса IA — одна строка), `C78` (усечение длинных запросов для
   IA/NASA/Wikimedia по измеренному градиенту).

Приёмка (офлайн, до платного прогона): `preferred_matches` ≥ порога владельца
на корпусе v2 (ориентир ≥ 6/24 или ≥ 5/14 — число называет владелец до старта);
0 `must_avoid_escaped`; двуязычный клип выигрывает scene_003 на реплее LIVE-5.

### P2 · Движение (1–2 сессии, $0 офлайн; проверка — на LIVE-6)

- Video-эндпоинты Pexels/Pixabay получают `orientation`/вертикальный фильтр

- Окно промоушена видео (`media_policy.py:114-195`) — не «первые 5», а «любое
  не отклонённое видео того же класса поддержки в шортлисте после дедупликации».
- Метаданные видео: тег-строку Pixabay и слаг Pexels читать как `tags`, а не как
  описание-заглушку.
- `C75`/`C76` (Wikimedia video: mime `application/ogg`, фильтр после пяти) —
  дёшево, но материала добавит мало; ниже приоритетом.
- Ken Burns на стиллах уже есть — оставить как fallback; политика канала «стиллы
  допустимы» — opt-in, не молчание.

Приёмка: офлайн — видео присутствует в дедуплицированном шортлисте ≥ 3/5 сцен

### P3 · Читаемость и дефолты (1 сессия, $0)

- Субтитры по умолчанию `documentary` для `fullscreen_voiceover_v1` (В10) на

- Дефолт `--voice-provider` — из `channel_config`, а не `disabled`; при

- Wizard показывает и спрашивает режим завершения; `draft_complete` — не молча.
- Хук-заголовок: первая сцена получает текстовый слой из `hook`-фразы (ASS-слой
  или `drawtext`, safe area над субтитрами) — **owner decision**, потому что

### P4 · Честность витрины и приёмка (1–2 сессии, $0)

- Каталог: `tiktok`/`stories` → `planned`; `supported_input_types` — по факту;

- `preview_render`: честный статус (`not_applicable`/`blocked` в отчёте use

- Export: не завершаться при `blocked` рендере; черновик не занимает поля

Приёмка: чек-лист PLAN-11 «интерфейс не предлагает того, чего нет» проходит на

### P5 · Экономика и безопасность прогона (1 сессия, $0)

- `ElevenLabsProvider.synthesize` через `require_network` (класс `voice_generate`
  или существующий, по решению владельца — это персистентная поверхность).
- `C87`: положительная оценка стоимости как блокер платного брифа (М4).
- Строка «стоимость / принято» в каждом отчёте прогона: $ брифа + символы TTS ×
  тариф канала (тариф — одна строка конфига).
- Время поиска: не отправлять запросы с `fallback_level`, уже давшим ноль у
  того же провайдера; ограничить провайдера после N нулевых выдач на сцену
  (54 нулевых попытки в LIVE-5); цель — поиск ≤ 5 мин.
- Strict: немое видео при отсутствии approval — `blocked`, не `completed`;
  `voice` на resume — сверка с текущим текстом (как в draft).

Приёмка: LIVE-6 поиск ≤ 5 мин; строка стоимости есть; тест RED→GREEN на
`require_network` для synthesize.

## 5. Решения владельца, нужные до старта

1. **Смысловой бриф по умолчанию для RU-каналов** — платный ($≈ 0,05 за проход
   плана) под project-scoped потолками, с показом ожидаемой стоимости до
   запуска (PD-5). Без него русский проект не ищет на стоке вообще; «офлайн
   бесплатно» = только локальная библиотека. Альтернатива — офлайн-глоссарий —
   даёт «Одна пчела цветка» и не рекомендуется.
2. Субтитры по умолчанию `documentary` (В10) и хук-заголовок — да/нет.
3. Пороги для P0/P1 (K/M) и порог `must_avoid_escaped = 0` — до начала работ.
4. Video-first: оставить 40 % или ввести режим «стиллы с движением» для канала.
5. Имя сетевого класса для `synthesize` и решение по `C87` (М4).
6. Тариф TTS для строки стоимости.

## 6. Что сознательно не предлагаю

Новый pipeline или второй selection-owner (PD-1, AGENTS.md); мультиагентный
цикл; Vision по умолчанию; репурпозер; UI/wizard-переделку; переписывание

документ-журнал; «пока починим всё в реестре» — только строки, которые бьют по
измеренным причинам.

## 7. Риски

- **Переобучение на солнце.** Все прогоны 13–15.08 — один текст. P1 может
  выиграть scene_003 и проиграть животных: поэтому корпус v2 обязан содержать
  LIVE-4, а LIVE-6 идёт по животному скрипту, и только потом три темы.
- **Зависимость от одного платного брифа.** Обратная сверка (P1.3) и
  `must_include` из детерминированного пути — страховка, не замена.
- **Время владельца.** Разметка ~10 сцен ≈ 30 мин на итерацию; без неё прибор
  не растёт.
- **Параллельная governance-ревизия** режет план, куда этот маршрут должен
  растворяться; порядок «сначала диета, потом продукт» удвоит срок — предлагаю
  вести их параллельно: P0–P2 не трогают документы плана кроме статусов.
- **Правки видео-эндпоинтов проверяются только живьём** (сколько вертикальных
  видео реально отдадут API — офлайн неизвестно).

## 8. Ограничения предложения

Оценки в сессиях — из состава слайсов и размера правок, не из измерений; цены —
из фактических $0,15 и тарифов брифа; часть решений (хук, стиллы, класс сети)
намеренно оставлена владельцу. Предложение не рецензировалось независимо.
