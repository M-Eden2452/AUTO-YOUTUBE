# AI-YouTube: объяснение проекта

## 1. Что это за проект сейчас

AI-YouTube сейчас стоит понимать не как старый MVP только про мотивационные видео, а как локальную AI-систему для создания русскоязычных cinematic quote/thought videos.

Формат проекта:

- мысли великих людей;
- сильные фразы;
- цитаты;
- идеи из книг;
- фразы из фильмов, аниме и мультфильмов;
- мысли актеров, философов и публичных деятелей.

Главная цель проекта: автоматизировать путь от темы ролика до готового YouTube-пакета. Pipeline должен собрать идею, цитаты или мысли, сцены, визуальные ассеты, музыку, рендер-план, видеофайл, YouTube-метаданные и заметку для базы знаний.

Текущий рабочий пример все еще завязан на Jordan Peterson, но это скорее демонстрационный контент. Архитектура уже больше похожа на систему для интеллектуальных cinematic-видео с цитатами и идеями.

## 2. Какие технологии используются

**Python** - основной язык проекта. На нем написан `pipeline.py` и все модули в `src/`.

**venv** - локальное виртуальное окружение Python. Оно хранит установленные библиотеки отдельно от системы.

**pip** - менеджер пакетов Python. Через него ставятся зависимости из `requirements.txt`.

**MoviePy** - библиотека Python для сборки видео: клипы, кадры, текст, музыка, экспорт mp4.

**FFmpeg** - низкоуровневый инструмент для кодирования и склейки видео. В проекте используется через `imageio-ffmpeg` и MoviePy.

**OpenAI API** - потенциальный источник AI-генерации текстов, структурных планов, метаданных и изображений. В текущем `src/` большая часть контента пока зашита локально, а AI-точки отмечены как расширение.

**Pexels API** - поиск и скачивание визуальных ассетов. Сейчас используется для изображений через `src/asset_finder.py`; старый корневой `download_broll.py` искал видео.

**Pixabay API** - запасной источник изображений и потенциальный источник музыки. В текущей версии музыка фактически берется из локального файла, а Pixabay используется как fallback для картинок при наличии ключа.

**Obsidian** - человеческая база знаний. Туда удобно складывать идеи роликов, статусы, финальные заголовки, заметки, ссылки на ассеты и выводы по качеству.

**JSON** - машинный формат данных. Pipeline пишет в JSON планы, которые затем читают другие шаги.

**Markdown** - человекочитаемый формат документов и заметок. README, эти документы и Obsidian-заметки написаны в Markdown.

**Git** - система контроля версий. Она хранит историю изменений кода и документации.

**.env** - локальный файл секретов и API-ключей. Его нельзя коммитить и нельзя выводить в лог.

**config/video_style.json** - главный конфиг стиля и путей. В нем задаются тема, персона, стиль, размеры видео, fps, музыка, источники ассетов, пути к JSON-планам и настройки Obsidian.

## 3. Что делает каждая технология в этом проекте

Python запускает pipeline и связывает все шаги вместе.

venv изолирует зависимости проекта, чтобы версии библиотек не конфликтовали с другими Python-проектами.

pip устанавливает MoviePy, Pillow, requests, OpenAI SDK, python-dotenv и другие библиотеки.

MoviePy создает видеоклипы, генерирует кадры с текстом, читает видеофайлы и добавляет звук.

FFmpeg кодирует mp4 и склеивает временные клипы сцен в один файл.

OpenAI API должен использоваться для будущей генерации сценариев, цитат, планов, метаданных и изображений. Сейчас в коде есть зависимости и заготовки, но основной рабочий pipeline может работать на локально заданных данных.

Pexels API ищет и скачивает изображения для сцен, если есть `PEXELS_API_KEY`.

Pixabay API используется как запасной источник изображений, если есть `PIXABAY_API_KEY`. Для музыки сейчас есть план и рекомендации, но надежное автоскачивание не реализовано.

Obsidian хранит итоговую человеческую карточку ролика: тему, статус, заголовки, описание, сцены, ассеты, ссылки на JSON и следующие действия.

JSON хранит промежуточные машинные структуры: quote plan, scene plan, asset plan, render plan, music plan, metadata, self-eval и stage log.

Markdown хранит README, документацию и Obsidian-заметки.

Git сохраняет историю изменений кода, конфигов и документации. Медиа, `.env`, venv и временные файлы должны оставаться вне Git.

`.env` хранит локальные секреты: `OPENAI_API_KEY`, `PEXELS_API_KEY`, `PIXABAY_API_KEY` и другие ключи.

`config/video_style.json` управляет темой ролика, стилем, длительностью, размерами, музыкой, источниками ассетов и экспортом в Obsidian.

## 4. Как работает pipeline по шагам

Главная точка входа - `pipeline.py`.

### `python pipeline.py --dev`

Dev-режим делает короткое быстрое превью:

1. Загружает `config/video_style.json`.
2. Включает `dev_mode`.
3. Ограничивает сцену короткой длительностью.
4. Создает `quote_plan`.
5. Создает `youtube_metadata`.
6. Создает короткий `scene_plan`, обычно из одной сцены.
7. Создает `intro_plan`.
8. Создает `music_plan`.
9. Создает `asset_plan`.
10. Создает `render_plan`.
11. Рендерит `outputs/final_preview.mp4`.
12. Пишет `outputs/self_eval.json`.
13. Если Obsidian включен, экспортирует заметку в vault или в `outputs/obsidian_note_preview.md`.

### `python pipeline.py --prod`

Production-режим использует production-настройки:

- `prod_resolution`;
- `prod_fps`;
- `prod_scene_duration`;
- `prod_output_filename`;
- `prod_font_size`.

Он собирает полный план сцен и рендерит `outputs/final_video.mp4`. Это более тяжелая операция, поэтому ее нельзя запускать как обычную проверку без явной необходимости.

### `python pipeline.py --skip-render`

Этот режим обновляет планы и метаданные, но пропускает рендер видео.

Он полезен, когда нужно проверить структуру JSON, YouTube-описание или Obsidian-заметку, не тратя время на MoviePy/FFmpeg.

При этом `self_eval.json` получает статус, что рендер был пропущен намеренно.

### `python pipeline.py --export-obsidian`

Этот режим не строит весь pipeline заново. Он берет уже готовые файлы из `outputs/` и создает Obsidian-заметку.

Если путь к vault существует, заметка пишется туда. Если нет и включен fallback, создается `outputs/obsidian_note_preview.md`.

### `python pipeline.py --no-obsidian`

Этот флаг отключает экспорт в Obsidian только для текущего запуска.

Например:

```bash
python pipeline.py --dev --no-obsidian
```

Так можно проверить рендер и JSON, не меняя базу Obsidian.

## 5. Какие файлы создаются и зачем

`outputs/quote_plan.json` - план цитат, мыслей и карточек текста. Содержит тему, персону, язык, источник, дисклеймер и список элементов.

`outputs/scene_plan.json` - план сцен. Содержит порядок сцен, длительность, тип сцены, текст на экране, автора, стиль, запросы для изображений и переходы.

`outputs/asset_plan.json` - план ассетов. Показывает, какие изображения, placeholder-картинки, b-roll-ассеты и музыка будут использоваться.

`outputs/render_plan.json` - технический план рендера: выходной файл, silent-видео, temp-папка, разрешение, fps, длительность, количество сцен, стратегия рендера.

`outputs/music_plan.json` - план музыки: найден ли локальный файл, какой путь использовать, громкость, рекомендации и предупреждения.

`outputs/youtube_metadata.json` - YouTube-пакет: варианты заголовков, выбранный заголовок, описание, теги, ключевые слова, идея thumbnail, shorts hook и community post.

`outputs/self_eval.json` - результат самопроверки после рендера или после `--skip-render`: проверки, предупреждения и общий статус.

`outputs/render_stage.json` - журнал стадий рендера. Нужен для диагностики: где начался рендер, где прошла валидация, где добавлялась музыка, где была ошибка.

`outputs/final_preview.mp4` - короткое dev-видео для быстрой проверки.

`outputs/final_video.mp4` - production-видео.

`outputs/obsidian_note_preview.md` - fallback-заметка для Obsidian, если vault недоступен или нужно сохранить preview-заметку внутри проекта.

## 6. Как устроен процесс создания сценария / текста / идей

Сейчас идея ролика задается в `config/video_style.json`:

- `video_type`;
- `topic`;
- `person`;
- `franchise`;
- `language`;
- `quote_source`;
- `visual_style`;
- `image_style`;
- `intro_style`.

Цитаты и мысли сейчас хранятся в коде `src/quote_generator.py`, в списке `PRODUCTION_ITEMS`. Это рабочий MVP-способ, но для дальнейшего развития лучше вынести контент в Obsidian, JSON или отдельные data-файлы.

Карточки сцен создаются в `src/scene_planner.py`. В dev-режиме создается короткая сцена. В production-режиме создаются intro, thought-сцены и final-сцена.

Заголовки, описание, теги, thumbnail idea и shorts hook создаются в `src/youtube_metadata.py`.

Визуальные ассеты подбираются в `src/asset_finder.py`. Там используются локальные файлы, Pexels, Pixabay или placeholder.

Музыка описывается в `src/music_finder.py`. Сейчас основной надежный путь - локальный `music/background.mp3`.

Промпты и шаблоны сейчас частично находятся прямо в Python-коде и в `config/video_style.json`. Старые корневые скрипты тоже содержат промпты, но они относятся к старому MVP и не являются частью текущего `pipeline.py`.

Файлы, отвечающие за генерацию:

- `src/quote_generator.py` - quote/idea plan;
- `src/scene_planner.py` - scene plan;
- `src/youtube_metadata.py` - YouTube metadata;
- `src/asset_finder.py` - asset plan;
- `src/music_finder.py` - music plan;
- `src/video_renderer.py` - render plan и рендер;
- `src/obsidian_exporter.py` - Obsidian note.

## 7. Что хранить в Obsidian

Obsidian нужен человеку. Он должен быть местом, где удобно думать, планировать, сравнивать идеи и вести production-статусы.

Obsidian стоит использовать для:

- идей видео;
- тем будущих роликов;
- статусов production;
- финальных заголовков;
- финальных описаний;
- заметок по стилю;
- ручных правок;
- списка источников;
- ссылок на ассеты;
- ссылок на итоговые mp4;
- наблюдений по качеству;
- планов следующих видео;
- серий и рубрик;
- ручной проверки цитат и авторских прав.

Рекомендуемая структура:

```text
YouTube/
  Цитаты/
  Великие люди/
  Фильмы/
  Аниме/
  Мультфильмы/
  Идеи/
  Готовые ролики/
  Шаблоны/
  Источники/
  Стили/
  Серии/
```

Один ролик лучше хранить как одну Markdown-заметку. В ней должны быть:

- тема;
- источник;
- статус;
- выбранный формат;
- цитаты или идеи;
- структура сцен;
- финальный заголовок;
- описание;
- теги;
- ссылки на JSON-планы;
- ссылка на mp4;
- ручные замечания;
- выводы после публикации.

## 8. Что хранить в JSON

JSON нужен коду. Это машинный формат, который pipeline может стабильно читать и писать.

В JSON стоит хранить:

- `quote_plan`;
- `scene_plan`;
- `asset_plan`;
- `render_plan`;
- `music_plan`;
- `metadata`;
- `self_eval`;
- `stage status`.

Почему так:

- JSON легко читать из Python;
- JSON можно валидировать;
- JSON хорошо подходит для промежуточных структур;
- JSON не должен быть главным местом для человеческих заметок;
- JSON удобен как снимок состояния конкретного запуска pipeline.

Простое правило:

```text
JSON нужен коду.
Obsidian нужен человеку.
```

## 9. Что хранить в TXT/MD внутри проекта

Внутри проекта можно хранить:

- `README.md`;
- техническую документацию в `docs/`;
- roadmap;
- cleanup reports;
- prompts, если они являются частью кода проекта;
- временные черновики, если они нужны для разработки и не содержат секретов.

TXT-файлы в `outputs/` лучше считать временными артефактами старого MVP, если они не используются текущим pipeline.

Markdown внутри `docs/` - хорошее место для объяснения архитектуры, правил запуска, планов чистки и будущих решений.

## 10. Архитектура knowledge base

Лучший вариант: один ролик = одна Markdown-заметка в Obsidian.

Pipeline может работать так:

1. Человек создает или выбирает заметку в Obsidian.
2. В заметке есть тема, источник, рубрика, статус, цитаты, стиль и ссылки.
3. Pipeline читает входные данные или получает их через экспорт.
4. Pipeline создает JSON-планы и видео.
5. Pipeline обновляет заметку: добавляет заголовки, описание, сцены, ассеты, ссылки на итоговый mp4 и self-eval.

Шаблоны роликов лучше хранить в Obsidian:

- `Шаблоны/Цитаты великого человека.md`;
- `Шаблоны/Фраза из фильма.md`;
- `Шаблоны/Идея из книги.md`;
- `Шаблоны/Аниме-фраза.md`;
- `Шаблоны/Серия философских мыслей.md`.

Стили роликов можно хранить в двух местах:

- в Obsidian - как человеческое описание стиля;
- в `config/video_style.json` или будущих JSON-конфигах - как машинные параметры для pipeline.

Списки авторов, фильмов, аниме и источников лучше хранить в Obsidian как базу знаний:

- `Источники/Авторы.md`;
- `Источники/Книги.md`;
- `Источники/Фильмы.md`;
- `Источники/Аниме.md`;
- `Источники/Мультфильмы.md`.

Для серий видео можно завести папку `Серии/`:

```text
Серии/
  10 мыслей стоиков/
  Фразы из аниме о силе/
  Идеи из книг о дисциплине/
  Сильные фразы из фильмов/
```

Каждая серия может содержать индексную заметку со списком роликов, статусами и ссылками на итоговые видео.

## 11. Текущая архитектура файлов

`pipeline.py` - главный orchestrator. Он вызывает функции из `src/`.

`config/video_style.json` - главный конфиг ролика и стиля.

`src/` - актуальное рабочее ядро.

`outputs/` - промежуточные JSON и итоговые/временные видео. JSON-файлы сейчас отслеживаются Git, mp4 и txt должны оставаться временными.

`assets/` - локальные и скачанные визуальные ассеты. Большие медиа не нужно коммитить.

`music/` - локальная музыка. `music/background.mp3` нужен для текущих запусков, но mp3 не должен попадать в Git.

`subtitles/` - пустая папка-заготовка. Сейчас pipeline ее не использует.

`scripts/` - пустая папка-заготовка. Сейчас pipeline ее не использует.

Корневые скрипты `main.py`, `scene_planner.py`, `scene_plan_json.py`, `download_broll.py`, `render_from_scene_plan.py`, `assemble_broll_video.py`, `assemble_broll_with_text.py`, `add_music.py` относятся к старому MVP и дублируют части `src/`.

## 12. Что нельзя трогать без отдельного решения

Нельзя трогать или коммитить:

- `.env`;
- `venv/`;
- mp4/mp3/mov/wav;
- большие ассеты;
- API-ключи;
- чужие локальные изменения;
- production-видео без явной задачи;
- файлы в Obsidian vault без понимания, что именно обновляется.

Нельзя удалять молча:

- старые корневые скрипты;
- старые outputs;
- `assets/broll/`;
- `music/background.mp3`;
- временные render-файлы.

Сначала нужен отчет и подтверждение.
